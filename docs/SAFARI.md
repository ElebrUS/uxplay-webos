# Прямое видео из Safari на Rockhopper 1.4

Этот отчёт описывает отдельную сборку 0.2.0. В версии 0.3.0 этот режим входит в [основной приёмник](UNIFIED.md).

Отдельное приложение **UxPlay Safari lab** (`com.github.danlflh.uxplaywebos.safari`) работает рядом с приёмником зеркалирования 0.2.0. Оно принимает legacy AirPlay POST `/play` из панели видео Safari. Сборка проверена на LG 55LB680V-ZD с webOS 1.4.0.

[Откройте доклад WWDC19 в Safari](https://developer.apple.com/videos/play/wwdc2019/501/), запустите его, затем выберите **UxPlay Safari lab** кнопкой AirPlay в самом видео. При первом подключении Safari может запросить PIN, который показан в окне телевизора.

В файле `safari-source.txt` первая строка содержит ожидаемый URL в запросе Safari, вторая — URL файла для воспроизведения. Профиль WWDC принимает адрес основного HLS-плейлиста и воспроизводит официальный SD MP4 этой же записи (H.264 640×360, AAC-LC 48 кГц). Телевизор загружает MP4 напрямую с CDN, проверяет TLS-сертификат по системному набору CA, декодирует H.264 и выводит звук через SDL. Для других страниц нужен профиль с проверенным прямым MP4. Встроенная обработка произвольных HLS-плейлистов, HEVC и DRM отсутствует.

## Сборка

На macOS ARM64 выполните `tools/build.sh --safari`. Зависимости зафиксированы в `dependencies.lock.json`. Пакет сохраняется в `dist/com.github.danlflh.uxplaywebos.safari_0.2.0_arm.ipk`. Установка использует обычный `ares-install`. Исходный приёмник собирается командой `tools/build.sh`.

Для изолированного теста бинарника из временного каталога можно задать `UXPLAY_DIRECT_URL` и `UXPLAY_DIRECT_MEDIA_URL`. Файл `uxplay.log` рядом с бинарником фиксирует приём запроса, открытие потока, количество кадров и аудиопакетов. Переменная `UXPLAY_TRACE=1` добавляет этапы настройки соединения.

## Проверка

- Safari запросил тестовый HTTP MP4. Телевизор вывел 360 из 360 кадров и обработал 517 аудиопакетов.
- На публичной странице Apple Safari отправил настоящий POST `/play`. Телевизор открыл официальный HTTPS MP4, декодировал H.264 и преобразовал AAC 48 кГц для выхода SDL. Пользователь подтвердил изображение и звук.
- Нативный ARM-бинарник прошёл аудит ELF и проверку загрузчика. Штатный GStreamer-путь через `lpsink` оставался на этапе preroll, поэтому эксперимент выводит видео программным декодером.
- Точность перемотки и синхронизация в миллисекундах, длительная стабильность и работа с другими сайтами не измерены.

Штатные `ares-install` и `ares-launch` завершились успешно для отдельного ID. Установленная копия обнаружилась по mDNS, приняла запрос со страницы Apple и продолжила вывод кадров и обработку звука после перемотки на 702,62 с. Контрольный снимок после перемотки зафиксировал не менее 299 показанных кадров и 470 аудиопакетов. Оба приложения версии 0.2.0 присутствуют на телевизоре.
