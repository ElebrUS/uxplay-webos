# Порт UxPlay для LG 55LB680V-ZD

## Что проверено на прошивке

SSH-инвентаризация указала Rockhopper 1.4.0-2536 и ядро 3.10.19-32.afro.6. Процессор имеет два ядра Cortex-A9 с VFPv3 и NEON. Системный загрузчик — `/lib/ld-linux.so.3`, glibc — 2.14.1. Системный C++ runtime — `/lib/libstdc++.so.6.0.16`.

Полученный с телевизора оригинальный исполняемый файл совпал побайтово с бинарником в официальном IPK v0.1.0. В его `DT_NEEDED` непосредственно присутствуют `libAcbAPI.so.1`, `libplayerAPIs.so.1`, SDL2 и SDL2_ttf. `src/media.cpp` вызывает ACB для регистрации media ID, выбора основного sink, передачи параметров видео, настройки окна и переходов состояния. Сам H.264 поступает в `StarfishMediaAPIs::Feed`. В поставляемой `libstdc++.so.6` и в прямых зависимостях целевого `libplayerAPIs.so.1` ACB отсутствует. Подгружаемые плагины оригинального плеера могут иметь собственные зависимости. [Исходник оригинального приёмника](https://github.com/danlflh/uxplay-webos/blob/acd387bb2f58eb0e23210d5fb0bb71af5e08ea36/src/media.cpp) и [официальный IPK v0.1.0](https://github.com/danlflh/uxplay-webos/releases/tag/v0.1.0).

| Путь | Что установлено | Что требуется для выбора |
|---|---|---|
| Starfish | На телевизоре экспортируются конструктор без аргументов, `Load(const char*, callback)` с трёхаргументным callback, `Feed(const char*)` и `Play()`. Исходник v0.1.0 использует конструктор с аргументом и `Load` с пользовательским указателем. По известному контракту более поздних систем `Feed` принимает JSON с адресом буфера, длиной, PTS и типом потока. Роль LS2 обслуживает собственные пространства имён pipeline и resource manager. | Установить точный ABI класса и обратных вызовов, проверить успешный `BUFFERSTREAM Load`, кормление Annex B и фактическое появление изображения в зарегистрированном видеослое. Без видимого кадра параметры задержки, памяти и синхронизации неизвестны. |
| GStreamer LG | `appsrc` и `h264parse` есть. `fakevdec` объявляет передачу данных внутреннему декодеру. `lpsink` принимает ANY на запрашиваемых pads, `lptsinkbin` описан как sink для текста. | Требуется тест цепочки с заданными caps, часами и зарегистрированной поверхностью, с проверкой появления кадров на панели. |
| NDL Media | `libNDL_media.so.1` экспортирует управление воспроизведением и положением окна. В её динамических символах нет `NDL_MediaFeedData`, `NDL_Esplayer*` либо `NDL_Direct*`. Зависит от uMedia API. | Формат и live-режим `NDL_MediaLoad` требуют отдельной проверки. Символов подачи access units в этом API не найдено. |

На Rockhopper проба с явной линковкой libdl дошла до загрузки DILE, но `LGNC_PLUGIN_Initialize` вернул −1 и декодер не открылся. Следующий эксперимент — получить причину отказа при запуске теста из штатного контекста native app. |

Задержка от камеры до экрана и пиковая память пока не измерены. |

## Сборка и runtime

`tools/build.sh` для macOS arm64 использует Python 3, CMake, Ninja, pkg-config, make, инструменты Xcode и webOS CLI (`ares-package`). Хеши SDK и архивов зависимостей находятся в `dependencies.lock.json`. Скрипт собирает статические библиотеки OpenSSL, libplist и FFmpeg, ARM-приложение и IPK в `dist/`. Порты AirPlay и DNS-SD обслуживает закреплённое ядро UxPlay. Базовый SDK содержит glibc 2.12.2, системная glibc в пакет не входит.

| Компонент | Совместимость |
|---|---|
| Исполняемый файл | ELF32, ARMv7-A, soft-float ABI, VFPv3/NEON, интерпретатор `/lib/ld-linux.so.3`. Известный максимальный импорт GLIBC — `GLIBC_2.7`. |
| C++ runtime | Исполняемый файл требует `GLIBCXX_3.4.29`, `CXXABI_1.3` и `CXXABI_ARM_1.3.3`. Поставляемая библиотека из SDK доступна через `$ORIGIN/lib` и сама требует до `GLIBC_2.6`. |
| SDL и библиотеки прошивки | Импортируемые SDL-функции найдены в образце с телевизора. Системные SDL2, Wayland, библиотека GPU и их зависимости разрешились нативным загрузчиком. |
| Мультимедиа и AirPlay | H.264, AAC, ALAC, ресемплинг, libplist и OpenSSL собраны статически. SDL callback читает PCM из кольца на 200 мс. Планировщик использует относительный PTS отправителя с начальной задержкой 200 мс; реальная задержка зависит от отправителя, рендера и аудиодрайвера. |
| Сторонние порты | Аппаратный путь danlflh требует ACB. UxAir на Starfish тоже требует ACB, а вариант NDL использует отдельный DirectMedia API. Обычная сборка FDH2 использует GStreamer с декодером и выводом на выбор. |

[Upstream UxPlay](https://github.com/FDH2/UxPlay/tree/48f5ce47c9ef694afccfac907c9e8828329657fe) и [варианты сборки UxAir](https://github.com/depius/uxair-webos/blob/d453a49cee41b0ce5e0f2d3654c3e658da776c73/CMakeLists.txt).

## Установка и диагностика

Пакет 0.2.0 имеет тот же ID, что и установленная 0.1.0, `com.github.danlflh.uxplaywebos`. Для установки через штатный установщик используйте `ares-install -d <имя-устройства> <файл.ipk>`, затем `ares-launch -d <имя-устройства> com.github.danlflh.uxplaywebos`. Перед обновлением сохраните каталог приложения и архив предыдущего релиза.

Из каталога отдельной тестовой копии можно проверить зависимости командой `/lib/ld-linux.so.3 --list ./uxplay-webos`. Для запуска из SSH используйте `UXPLAY_TRACE=1 ./uxplay-webos`. Журнал сохраняется рядом с программой в `uxplay.log`. `[trace] type = 110` означает запрос зеркалирования, `type = 96` — аудиоканал. `[stats]` показывает число обработанных пакетов, показанных кадров и переполнений. PIN выводится в окне приложения.

Для проверки программного пути есть `tools/test-software.sh`. На машине сборки он требует SDL2, FFmpeg с libx264, libavcodec и libavutil. Проверка 60 кадров каждого из двух тестовых потоков также была собрана для ARM и выполнена на телевизоре.

Экспериментальный бинарник LGNC собирается в обычном ARM-каталоге сборки командой `cmake -S . -B build -DBUILD_LGNC_PROBE=ON`, затем `cmake --build build --target lgnc-probe`. Для него нужен тестовый Annex B 640×360 с AUD перед каждым кадром и собственный идентификатор приложения. Проба может занять видеослой телевизора.
